1. НАЗНАЧЕНИЕ ПРОЕКТА
============================================================

Разработать локальную WEB-систему для одной IP-камеры, которая позволяет обычному пользователю через браузер:

- смотреть камеру в реальном времени;
- просматривать архив;
- находить события движения;
- воспроизводить записи;
- скачивать видеофрагменты;
- пользоваться системой с компьютера и мобильного телефона.

Система предназначена для домашнего использования.

Физический доступ к серверу/компьютеру не должен требоваться для обычных операций.

Пример пользовательского сценария:

1. Пользователь открывает сайт.
2. Авторизуется.
3. Видит одну камеру.
4. Нажимает "Смотреть".
5. При необходимости открывает архив.
6. Выбирает дату/время или событие движения.
7. Просматривает запись.
8. Нажимает "Скачать".

Система должна быть максимально простой для человека без технических знаний.


============================================================
2. ОСНОВНАЯ КОНЦЕПЦИЯ
============================================================

Приложение является исключительно WEB-приложением.

Отдельного desktop GUI, Windows-приложения, мобильного приложения или отдельного native-клиента не требуется.

Доступ к системе осуществляется через WEB-браузер.

Поддерживаемые сценарии:

- локальный доступ в домашней сети;
- возможность привязки домена;
- возможность дальнейшего безопасного доступа через Интернет.

Система должна быть рассчитана на работу на Debian 13.

Все серверные компоненты должны запускаться в Docker.

============================================================
16. EXPORT VIDEO
============================================================

При запросе диапазона:

1. Backend определяет необходимые сегменты.
2. Проверяет наличие файлов.
3. Объединяет необходимые сегменты.
4. При необходимости выполняет remux/transcode.
5. Создаёт MP4.
6. Возвращает ссылку на скачивание.

После скачивания временный export-файл должен удаляться автоматически через заданное время.

18. СЕГМЕНТАЦИЯ ВИДЕО
============================================================

Видео должно храниться небольшими сегментами.

Рекомендуемый размер:

1–5 минут.

Причины:

- удобный поиск;
- быстрый export;
- меньше риск потери большого файла;
- проще удалять старые записи;
- проще реализовать циклическую запись.

============================================================
20. ЦИКЛИЧЕСКАЯ ЗАПИСЬ / OVERWRITE
============================================================

Это обязательное требование.

При заполнении диска система НЕ должна останавливаться.

Система должна работать по принципу circular storage.

Алгоритм:

1. Система постоянно контролирует свободное место.
2. При достижении лимита хранения определяется самый старый сегмент.
3. Самый старый сегмент удаляется.
4. На его место продолжается запись новых данных.
5. Процесс повторяется автоматически.

Должен быть задан минимальный запас свободного места.

Например:

MAX_STORAGE_USAGE = 90%

MIN_FREE_SPACE = 10%

При достижении лимита:

старые записи -> удаляются

новые записи -> продолжают записываться.

Администратор должен иметь возможность настроить:

- максимальный объём хранения;
- минимальный свободный объём;
- минимальный срок хранения, если возможно совместить с ограничением места.

При конфликте требований приоритет имеет сохранение непрерывной записи.

24. MOTION EVENT
============================================================

При обнаружении движения создаётся событие.

Событие содержит:

- ID;
- дату;
- время начала;
- время окончания;
- длительность;
- motion score;
- thumbnail;
- ссылку на соответствующую запись.


============================================================
25. PRE-BUFFER
============================================================

Желательно реализовать pre-buffer.

Например:

Настройка:

PRE_BUFFER = 10 sec

Motion:

18:42:10

Сохранённый event:

18:42:00 - 18:42:30

Таким образом запись начинается немного раньше фактического обнаружения движения.


============================================================
26. THUMBNAILS
============================================================

Для motion event необходимо создавать thumbnail.

Thumbnail используется:

- в списке событий;
- в архиве;
- на мобильном устройстве.

Размер должен быть небольшим для быстрой загрузки.

============================================================
73. ПРИНЯТЫЕ ПРОЕКТНЫЕ РЕШЕНИЯ (v2.1)
============================================================

Решения приняты в ходе проектирования. Имеют приоритет над
общими формулировками предыдущих разделов при противоречиях.

------------------------------------------------------------
73.1 LIVE VIEW
------------------------------------------------------------

MVP: HLS (генерируется backend'ом через FFmpeg из RTSP).
Допустимая задержка live: 2–5 секунд.
WebRTC — цель для следующей версии (post-MVP), архитектура
не должна ему препятствовать.
MJPEG не используется.

------------------------------------------------------------
73.2 ВОСПРОИЗВЕДЕНИЕ АРХИВА
------------------------------------------------------------

Backend генерирует HLS-плейлист из существующих сегментов
на лету. Seek выполняется по плейлисту без склейки файлов.
Склейка сегментов в MP4 выполняется ТОЛЬКО для скачивания
(export), не для онлайн-просмотра.

------------------------------------------------------------
73.3 СУБ-ПОТОК КАМЕРЫ
------------------------------------------------------------

Если камера отдаёт второй (низкоразрешающий) RTSP-поток:

- основной поток: запись, export;
- суб-поток: motion detection, live preview.

В настройках камеры предусмотреть два RTSP URL
(основной и суб-поток). Если суб-потока нет — motion
detection работает на уменьшенной копии основного потока
(320x180), как описано в разделе 60.

------------------------------------------------------------
73.4 C++ ФРЕЙМВОРК И ЗАВИСИМОСТИ
------------------------------------------------------------

HTTP/WebSocket framework: Crow (header-only).
JSON: nlohmann/json.
PostgreSQL client: libpqxx.
Логирование: spdlog (structured logs).
Password hashing: argon2 (libargon2).
Сборка: CMake.
Зависимости: системные пакеты Debian 13 (apt) внутри
Docker-образа. vcpkg не используется.

------------------------------------------------------------
73.5 ПЕРВЫЙ ЗАПУСК / SETUP WIZARD
------------------------------------------------------------

При первом открытии системы (нет ни одного пользователя
в БД) показывается мастер первоначальной настройки:

1. Создание учётной записи администратора.
2. Настройка камеры (IP, ONVIF, RTSP).
3. Проверка соединения.
4. Завершение — переход на главную страницу.

Пока wizard не завершён, остальные страницы недоступны.
Дефолтных учётных данных (admin/admin) в системе нет.

------------------------------------------------------------
73.6 HTTPS
------------------------------------------------------------

В локальной сети система работает по HTTP.
HTTPS включается при привязке домена (Let's Encrypt,
контейнер certbot — опционально, post-MVP).
Самоподписанные сертификаты не используются.

------------------------------------------------------------
73.7 АУДИО
------------------------------------------------------------

Если камера передаёт аудиопоток — он записывается в
сегменты вместе с видео и воспроизводится в плеере.
В live view предусмотрен mute/unmute.
Если аудио в потоке нет — система работает без него.

------------------------------------------------------------
73.8 ЗНАЧЕНИЯ ПО УМОЛЧАНИЮ
------------------------------------------------------------

- Длительность сегмента: 5 минут.
- Pre-buffer: 10 секунд.
- MAX_STORAGE_USAGE: 90%.
- MIN_FREE_SPACE: 10%.
- Overwrite: включён по умолчанию.
- Сессия: HttpOnly cookie, срок жизни 7 дней.
- Аутентификация: только username + password (без email;
  формулировка "Email / Username" в разделе 42 отменяется).
- Язык интерфейса: русский; все строки в системе
  локализации (задел под английский).
